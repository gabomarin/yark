## What YARK does

The Workspace **Mods** tab stores CurseForge **Project IDs** per profile.

- **Enabled** IDs are passed at launch as `-mods=id1,id2,…`
- **Disabled** IDs stay on the profile until you turn them back on (no need to delete an ID to skip one boot)
- **Passive** IDs (row action, row menu, or detail drawer, on an enabled row) load their data with functionality disabled — for cluster transfer / “load data, no spawns”. They are sent only as `-passivemods=id1,id2,…`, never on `-mods=`, and the row shows a **Passive** badge. Disable a passive row and the passive mark is cleared.
- Newly added IDs start **disabled** — enable them explicitly before they appear on `-mods=`. Add shows a **Mod Added** toast (two can stay visible; a third drops the oldest). Disabled inventory rows are dimmed (thumb + text) while the Enabled switch stays full strength; row **Remove** stays red **subtle**. One CurseForge category sits under the mod name (Maps uses attention color; extra tags as +N with a hover list). The detail drawer can enable, disable, and remove a configured ID, add a Discover result to this server, and shows a Maps launch-token hint (current map unchanged).
- **IDs** copies All, Enabled, Disabled, or **selected** Project IDs in load order. Paste that list into **Add** — commas, spaces, or new lines all work. A row menu can copy one Project ID or its CurseForge URL.
- With mods on the list, **Add** shares the toolbar with **Find** and **Status** (Enabled, Disabled, or Passive). Filters only hide rows. Load order does not change, and drag stays off until you clear the filter.
- Check one or more rows to replace **Enable all** / **Disable all** / **Remove all disabled** with **Enable** / **Disable** / **Remove** for the selection (same icons; Remove stays red), plus **Clear**. Counts show **N selected** · active · disabled under those actions.
- Reorder without drag: row **More actions** (and right-click) offer **Move to top / up / down / bottom**; **Alt+↑/↓** moves a focused row; **Apply sort as load order** writes the current column sort into load order when no filter is hiding rows.
- **Open local folder** and **Clear downloaded files** (More actions kebab, context menu, and detail drawer) work on that mod’s ASA folders. Clear deletes them after confirm so the next Start can fetch again; both stay off while the server is running or no folders exist.
- When CurseForge has no usable page for a numeric Project ID, **Add Project ID** keeps the row without metadata until **Check CurseForge again**. Start still loads it once you enable it.
- **Discover** browses CurseForge on open: category filter, in-field search (icon / Enter), pagination, catalog sort from table headers (Name / Downloads / Updated), Clear sort back to Popularity, and **Hide already added** (off by default) to filter configured rows on the current page. Search / category / sort / page survive switching back from Server mods. The table scrolls in the panel with a fixed pagination footer. If the category list cannot load yet, Discover still works with a soft failure.
- Names / summaries / links come from a small Cloudflare Worker proxy and are cached locally
- The detail drawer can show a CurseForge **screenshot carousel** and a clamped plain-text **description** when inspect fetches get-by-id metadata

## Maps / custom worlds

CurseForge **Maps** packs are ordinary Project IDs on `-mods=`. ASA does **not** use legacy
`ActiveMapMod`. **`-MapModID=`** applies only to **official-token remasters** (see
[Profiles & ports](/docs/profiles-and-ports/)). A correct custom-map server needs **both**:

1. The map pack Project ID **enabled** on this Mods tab, and  
2. The author launch token selected under **Server Information → Map** (see [Profiles & ports](/docs/profiles-and-ports/))

### Happy path

**Fast path:** **New server** → **Map** → **Search Maps…** → pick a CurseForge Maps card → confirm
Map Name. YARK sets the launch token, links `mapModId`, and enables the Project ID in one step.

**From Mods (after create on an official map):**

1. Add the map pack Project ID (or URL) on Mods — it starts disabled  
2. **Enable** it — YARK shows a toast that the mod is available under Map; your current map is **not** changed  
3. Open the **Server** tab → **Map** → pick the pack under **Map mods**, use **Search Maps…**, or **Custom…** if you must type the token yourself  
4. Check **Launch** preview, then **Start**

Enabling a Maps mod never overwrites the map you already have. You choose when to switch.

If YARK can read a `Map Name:` / `Server Name:` / `*_WP` token from CurseForge metadata, the pack
appears under **Map mods** (the detail drawer also shows that token). Operator copy does **not**
assume CurseForge always lists the name — check the map community, wiki, or author notes when it
does not. If inference fails, use **Custom…** with the token from the author page, and keep the
map pack enabled on Mods.

<Aside type="tip">
  Start is blocked when a custom map’s linked map mod is missing, disabled, or unset. Fix the Map
  selection or enable the pack, then try again — see [Start, stop, restart](/docs/lifecycle/).
</Aside>

## What YARK does not do

<Aside type="caution">
  YARK does **not** download or install mod files into the dedicated server. You still need mod
  content available the way you normally would for ASA.
</Aside>

## Operator tips

1. Wrong Project IDs still get wired into launch if enabled — verify IDs on CurseForge
2. Restart after changing the enabled set so the new `-mods=` list applies
3. Back up the world before enabling mods a world already depends on (or before removing them)
4. Cluster members that transfer together usually need compatible mod sets
5. For map packs, confirm both **enabled on Mods** and the correct **Map** token before Start — a
   passive map pack is omitted from `-mods=`, so Mods shows a warning until you mark it active again
6. Row actions and right-click menus share the same Menu chrome as the icon buttons — use either path
7. Use **Hide already added** on Discover when you only want new packs on the current page
8. Prefer **Clear downloaded files** over Remove when you want ASA to refetch the same Project ID on the next Start

Discover is the supported CurseForge browse surface on this tab (beyond typing Project IDs or URLs).
