YARK

server manager

Built for people who host local ARK: Survival Ascended dedicated servers on Windows — profiles, SteamCMD, CurseForge mods, backups, logs, and INI configuration in one desktop app. Early builds are available on GitHub as an unsigned public prerelease — expect rough edges and breaking changes between versions.

Current development scope

Areas already being built and exercised in early public prerelease builds (Electron + React + TypeScript on Windows). This is not a shipping product checklist.

  • Multiple server profiles from a single desktop shell
  • Start, stop, restart, and force-stop dedicated instances
  • Install, update, and verify server files with SteamCMD
  • Create and restore backups; review operation history
  • Runtime, update, and backup logs
  • Cluster compliance checks and RCON command surface
  • Server Workspace with visual/raw INI editing and an on-demand configuration assistant
  • CurseForge Mods tab — Project IDs, enable/disable without dropping IDs, Worker-backed metadata, and launch-time -mods= for enabled mods
  • Settings for SteamCMD path, theme, and related app preferences
  • Official ARK network version from Wildcard’s public status CDN

What it is not

YARK is not a cloud host, not an ARK game client launcher, and not an official Wildcard product. It is an independent local manager for dedicated-server tooling you run on your own machine.

Privacy and data

Server profiles and app settings stay on your PC (local SQLite). There is no YARK cloud account. Network use covers SteamCMD content, Wildcard’s public official-status CDN for the displayed network version, and CurseForge mod metadata via a small Cloudflare Worker proxy hosted for the project (self-hostable from that folder). The desktop app never embeds a CurseForge API key: lookups send Project IDs / search queries only — not server profiles, passwords, or install paths — and returned names/summaries/links are cached locally.

Mods

The Server Workspace Mods tab manages CurseForge Project IDs per profile. Enabled IDs are passed at launch as -mods=; disabled IDs stay on the profile until you turn them back on. Names, summaries, and page links come from Worker-backed CurseForge metadata (cached locally). YARK wires launch IDs and metadata — it does not download or install mod files for you.

Security note

Admin and RCON passwords live in local profiles. Treat screenshots, shared logs, and exported configs carefully so secrets are not leaked.
