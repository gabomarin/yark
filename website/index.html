YARK

server manager

Built for people who host local ARK: Survival Ascended dedicated servers on Windows — profiles, SteamCMD, backups, logs, and INI configuration in one desktop app. Early builds are available on GitHub as an unsigned public prerelease — expect rough edges and breaking changes between versions.

Current development scope

Areas already being built and exercised in early public prerelease builds (Electron + React + TypeScript on Windows). This is not a shipping product checklist.

  • Multiple server profiles from a single desktop shell
  • Start, stop, restart, and force-stop dedicated instances
  • Install, update, and verify server files with SteamCMD
  • Create and restore backups; review operation history
  • Runtime, update, and backup logs
  • Cluster compliance checks and RCON command surface
  • Server Workspace with visual/raw INI editing and an on-demand configuration assistant
  • CurseForge mod Project IDs per server via the Server form (-mods=)
  • Official ARK network version from Wildcard’s public status CDN

Direction may change as development continues. Nothing here is a promise of a stable 1.0 ship date.

What it is not

YARK is not a cloud host, not an ARK game client launcher, and not an official Wildcard product. It is an independent local manager for dedicated-server tooling you run on your own machine.

Privacy and data

Server profiles and app settings stay on your PC (local SQLite). There is no YARK cloud account. Network use is limited to what the workflows need (for example SteamCMD content, and Wildcard’s public official-status CDN for the displayed network version). Future mod metadata lookups would only happen if you opt into that integration.

Mods

Today you attach CurseForge Project IDs on the Server form; they are passed through as dedicated-server -mods= launch arguments. A richer Mods browser (search, metadata, ordering UX) is planned — not required for basic ID-based launch.

Security note

Admin and RCON passwords live in local profiles. Treat screenshots, shared logs, and exported configs carefully so secrets are not leaked.
